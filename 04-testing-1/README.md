## A. Bit++

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/719112/problem/A)

Изначально `x = 0`. Каждая строка содержит либо два плюса, либо два минуса; положение `X` значения не имеет. Если в строке встречается `+`, увеличиваем `x`, иначе уменьшаем.

После обработки первых $k$ строк `x` равен результату первых $k$ команд, поэтому после последней строки получаем результат всей программы.

Сложность: $O(n)$ по времени и $O(1)$ дополнительной памяти.

→ Решение: [`examples/a_bitpp.cpp`](examples/a_bitpp.cpp).

> [!WARNING]
> Проверять только первый символ нельзя: операция может быть записана как `X++`.

## B. Мишка и старший брат

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/719112/problem/B)

Пока вес Лимака не стал строго больше веса Боба, моделируем один год: первый вес умножаем на `3`, второй — на `2`, число лет увеличиваем на единицу.

После $y$ итераций веса равны $a\cdot3^y$ и $b\cdot2^y$. Цикл останавливается в первый год со строгим превосходством, поэтому счётчик минимален.

Сложность: $O(\log(b/a))$ по времени и $O(1)$ по памяти.

→ Решение: [`examples/b_bear_and_big_brother.cpp`](examples/b_bear_and_big_brother.cpp).

> [!WARNING]
> Равных весов недостаточно, поэтому цикл работает при `a <= b`.

## C. Любимая последовательность

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/719112/problem/C)

В последовательности на доске элементы с нечётными номерами исходной последовательности расположены слева направо, а элементы с чётными — справа налево. Восстанавливаем ответ, по очереди беря левый, правый, левый, правый элементы массива.

Первый указатель выдаёт $a_1,a_3,a_5,\ldots$, второй — $a_2,a_4,a_6,\ldots$. Их чередование восстанавливает $a_1,a_2,\ldots,a_n$.

Сложность одного набора: $O(n)$ по времени и $O(n)$ памяти.

→ Решение: [`examples/c_favorite_sequence.cpp`](examples/c_favorite_sequence.cpp).

## D. Приезд генерала

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/719112/problem/D)

Нужно передвинуть максимального солдата в начало, а минимального — в конец. Выгодно взять самое левое вхождение максимума и самое правое вхождение минимума.

Для индексов `max_pos` и `min_pos` с нуля ответ сначала равен

$$
max\_pos + (n - 1 - min\_pos).
$$

Если максимум расположен правее минимума, при движении максимума влево минимум сдвинется на одну позицию вправо. Тогда вычитаем единицу.

Сложность: $O(n)$ по времени и $O(n)$ памяти.

→ Решение: [`examples/d_arrival_of_the_general.cpp`](examples/d_arrival_of_the_general.cpp).

> [!IMPORTANT]
> Для максимума обновляем позицию только при `>`, а для минимума — при `<=`: так находятся первое и последнее подходящие вхождения.

## E. Ближайшее число

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/719112/problem/E)

Перебираем массив. Новый элемент становится ответом, если его расстояние $|a_i-x|$ меньше текущего или если расстояния равны, но само значение меньше.

После каждой итерации хранится лучший элемент среди уже просмотренных. Значит, после полного перебора найден лучший элемент всего массива с учётом правила разрешения ничьей.

Сложность: $O(n)$ по времени и $O(n)$ памяти.

→ Решение: [`examples/e_nearest_number.cpp`](examples/e_nearest_number.cpp).

## F. Разброс

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/719112/problem/F)

Значения могут быть близки к $\pm2\cdot10^9$, но разница между минимумом и максимумом не превышает $10^7$. Применяем сортировку подсчётом со сдвигом:

1. находим минимум и максимум;
2. число `value` учитываем в ячейке `value - minimum`;
3. обходим частоты слева направо и восстанавливаем числа.

Ячейка $d$ хранит число вхождений значения $minimum+d$. Индексы идут по возрастанию, поэтому результат отсортирован и сохраняет все элементы.

Сложность: $O(n+r)$ по времени и $O(r)$ памяти, где $r=maximum-minimum\le10^7$.

→ Решение: [`examples/f_spread.cpp`](examples/f_spread.cpp).

> [!WARNING]
> Размер массива частот зависит от разброса, а не от абсолютного значения чисел.

## G. Ваня и фонари

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/719112/problem/G)

Сортируем координаты фонарей. Нужный радиус равен максимуму из:

- расстояния от `0` до первого фонаря;
- половины каждого промежутка между соседними фонарями;
- расстояния от последнего фонаря до `l`.

На краях участок освещает только один фонарь, а внутренний промежуток делят два соседних. Меньший радиус оставит тёмным участок, который дал максимум.

Сложность: $O(n\log n)$ по времени и $O(n)$ памяти.

→ Решение: [`examples/g_vanya_and_lanterns.cpp`](examples/g_vanya_and_lanterns.cpp).

> [!WARNING]
> Внутренние промежутки делятся пополам, крайние — нет.

## ZA. Монотонный фрагмент

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/719112/problem/ZA)

Поддерживаем длины строго возрастающего и строго убывающего фрагментов, заканчивающихся в текущем элементе. Если нужное сравнение нарушено, соответствующая длина начинается заново с единицы. Равные элементы прерывают оба фрагмента, а первый `0` завершает ввод.

В каждый момент обе длины точно описывают лучшие фрагменты своего направления с текущим правым концом. Максимум по всем правым концам является ответом.

Сложность: $O(n)$ по времени и $O(1)$ памяти.

→ Решение: [`examples/za_monotonic_fragment.cpp`](examples/za_monotonic_fragment.cpp).

## ZB. Оптимальная пара

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/719112/problem/ZB)

Для фиксированного $j$ разность $a_j-a_i$ минимальна, если слева выбрать максимальное $a_i$. При проходе слева направо храним максимум префикса и его позицию, а для каждого $j$ проверяем одну лучшую пару.

Мы рассматриваем лучшую пару для каждого возможного правого конца. Минимум среди них является глобальным минимумом.

Сложность: $O(n)$ по времени и $O(1)$ дополнительной памяти.

→ Решение: [`examples/zb_optimal_pair.cpp`](examples/zb_optimal_pair.cpp).

> [!CAUTION]
> Минимизируется $a_j-a_i$, а не модуль разности. Ответ может быть отрицательным.

## ZC. «Сортировка» с конфеткой

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/719112/problem/ZC)

Буквально выполняем описанную пузырьковую сортировку. Для каждой соседней инверсии проверяем, запрещён ли обмен этой пары значений. Разрешённую пару меняем местами, запрещённую оставляем.

Запрещённые пары симметричны. Храним их в плоской таблице $(n+1)\times(n+1)$: проверка занимает $O(1)$, а максимальный объём — около 25 МБ.

Каждый шаг совпадает с шагом процесса из условия. Если целый проход не сделал ни одного обмена, следующий увидит тот же массив и тоже ничего не изменит, поэтому можно завершиться раньше.

Сложность: $O(n^2)$ по времени и $O(n^2)$ памяти.

→ Решение: [`examples/zc_candy_sort.cpp`](examples/zc_candy_sort.cpp).

## Итоги тестирования

Задачи проверяют приёмы первых трёх тематических занятий:

- прямое моделирование — A, B и ZC;
- два указателя и восстановление последовательности — C;
- выбор экстремальных позиций — D;
- линейный перебор с дополнительным условием — E, ZA и ZB;
- сортировки и использование ограниченного диапазона — F и G.

Перед отправкой решения полезно отдельно проверить строгие неравенства, одинаковые значения, крайние элементы массива и тип выражения при делении на два.
