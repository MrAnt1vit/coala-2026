## 1. Футбол

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/724153/problem/1)

Для каждого забитого гола увеличиваем счётчик команды в `map<string, int>`. Затем выбираем название с максимальным числом голов. По условию победитель единственный.

После обработки первых $k$ голов словарь хранит точный счёт матча на этот момент. После последней записи максимальная частота принадлежит победителю.

Сложность: $O(n\log t)$ по времени, где $t$ — число команд, и $O(t)$ памяти.

→ Решение: [`examples/01_football.cpp`](examples/01_football.cpp).

> [!TIP]
> Для двух команд достаточно двух счётчиков, но словарь делает решение короче и не зависит от количества разных названий.

## 2. Простой стек

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/724153/problem/2)

Стек работает по принципу LIFO: последним добавили — первым удалили. Так как по условию одновременно хранится не больше 100 элементов и запрещены готовые контейнеры, используем обычный массив и переменную `size`:

- `push x`: записать `x` в `data[size]`, затем увеличить `size`;
- `pop`: уменьшить `size`, затем вывести `data[size]`;
- `back`: вывести `data[size - 1]`, не меняя размер;
- `clear`: присвоить `size = 0`;
- `size`: вывести текущий размер.

Элементы стека всегда лежат в `data[0..size)`, а его вершина — в `data[size - 1]`. Каждая команда сохраняет этот инвариант.

Сложность каждой команды: $O(1)$ по времени; весь массив занимает $O(1)$ памяти, потому что его размер ограничен 100.

→ Решение: [`examples/02_simple_stack.cpp`](examples/02_simple_stack.cpp).

> [!WARNING]
> Команды `pop` и `back` в этом условии корректны. В версиях задачи с ошибками пустой стек нужно проверять отдельно.

## 3. Плохие цены

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/724153/problem/3)

Цена в день `i` плохая, если справа существует строго меньшая цена. Идём с конца и храним минимум среди уже просмотренного суффикса.

- если `a[i] > suffix_min`, день плохой;
- иначе обновляем `suffix_min = a[i]`.

Перед обработкой позиции `i` переменная `suffix_min` равна минимуму на позициях правее. Поэтому сравнение в точности проверяет определение плохой цены.

Сложность одного набора: $O(n)$ по времени и $O(n)$ памяти для массива.

→ Решение: [`examples/03_bad_prices.cpp`](examples/03_bad_prices.cpp).

> [!IMPORTANT]
> При равных ценах день не считается плохим: справа должна быть цена **строго меньше**.

## 4. Забор

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/724153/problem/4)

Нужно найти $k$ соседних досок с минимальной суммарной высотой. Сначала считаем сумму первого окна. При сдвиге вправо удаляем ушедшую высоту и добавляем новую:

```cpp
window += height[right] - height[right - k];
```

Каждый возможный отрезок длины $k$ рассматривается ровно один раз, поэтому запомненный минимум и есть ответ. Индекс в условии начинается с единицы.

Сложность: $O(n)$ по времени и $O(n)$ памяти.

→ Решение: [`examples/04_fence.cpp`](examples/04_fence.cpp).

> [!WARNING]
> Обновляйте ответ только при строгом улучшении: тогда при равных суммах останется самый левый подходящий отрезок.

## 5. Польшар и Игра

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/724153/problem/5)

Пусть `common` слов знают оба игрока. Польшар начинает и при возможности называет общее слово: оно тратит ход Польшара и одновременно отнимает вариант у Врагошара. Поэтому общие слова игроки выгодно разбирают в начале.

После них остаются только уникальные слова. Если `common` нечётно, следующий ход снова делает Врагошар; если чётно — Польшар. Отсюда Польшар выигрывает, когда:

```text
only_first > only_second
или
only_first == only_second и common нечётно.
```

Пересечение удобно посчитать двумя множествами.

Сложность: $O((n+m)\log(n+m))$ операций со строками и $O(n+m)$ памяти.

→ Решение: [`examples/05_polandball_game.cpp`](examples/05_polandball_game.cpp).

## 6. Быстрый поиск в массиве

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/724153/problem/6)

После сортировки числа из диапазона $[l,r]$ образуют один непрерывный фрагмент:

- `lower_bound(l)` находит первый элемент `>= l`;
- `upper_bound(r)` находит первый элемент `> r`.

Разность итераторов равна количеству элементов между этими границами.

Сортировка занимает $O(n\log n)$, каждый из $q$ запросов — $O(\log n)$. Общая сложность: $O((n+q)\log n)$ по времени и $O(n)$ памяти.

→ Решение: [`examples/06_fast_search.cpp`](examples/06_fast_search.cpp).

> [!CAUTION]
> Правая граница включена, поэтому для неё нужен именно `upper_bound(r)`, а не `lower_bound(r)`.

## 7. Очень Легкая Задача

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/724153/problem/7)

Первую копию может делать только один ксерокс, поэтому на неё уйдёт `min(x, y)` секунд. После этого оба аппарата работают одновременно.

Для времени `time` после первой копии число новых листов равно

$$
\left\lfloor\frac{time}{x}\right\rfloor+
\left\lfloor\frac{time}{y}\right\rfloor.
$$

Предикат «за `time` секунд можно получить оставшиеся $n-1$ копий» монотонен: если времени хватило, любое большее тоже подойдёт. Ищем первое подходящее время бинарным поиском и прибавляем время первой копии.

Сложность: $O(\log(n\max(x,y)))$ по времени и $O(1)$ памяти.

→ Решение: [`examples/07_very_easy_task.cpp`](examples/07_very_easy_task.cpp).

> [!IMPORTANT]
> При `n = 1` после первой копии больше ничего печатать не нужно.

## ZA. Плагин

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/724153/problem/ZA)

Когда два одинаковых соседних символа исчезают, новые соседи тоже могут совпасть. Храним уже обработанную часть строки как стек:

- если текущий символ равен последнему в стеке, удаляем последний;
- иначе добавляем текущий символ.

После каждого шага стек равен полностью сокращённому результату для прочитанного префикса. Значит, после всей строки в нём останется окончательный ответ.

Сложность: $O(n)$ по времени и $O(n)$ памяти.

→ Решение: [`examples/za_plugin.cpp`](examples/za_plugin.cpp).

## ZB. Кефа и компания

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/724153/problem/ZB)

Сортируем друзей по количеству денег. Подходящая компания становится окном, в котором разность между самым богатым и самым бедным строго меньше `d`.

Двигаем правую границу, добавляем дружелюбность нового друга и сдвигаем левую, пока `money[right] - money[left] >= d`. Обе границы движутся только вправо, поэтому после сортировки проход линейный.

Сложность: $O(n\log n)$ по времени и $O(n)$ памяти.

→ Решение: [`examples/zb_kefa_and_company.cpp`](examples/zb_kefa_and_company.cpp).

> [!WARNING]
> В условии разница должна быть **строго меньше** `d`, поэтому окно с разницей ровно `d` уже недопустимо.

## ZC. Гамбургеры

→ [Условие](https://codeforces.com/group/ByhdE7NWBK/contest/724153/problem/ZC)

Сначала считаем, сколько булочек `B`, котлет `S` и сыра `C` нужно на один гамбургер. Для кандидата `count` стоимость недостающих продуктов равна

$$
\sum_{product}
\max(0, need_{product}\cdot count-have_{product})\cdot price_{product}.
$$

Если денег хватает на `count` гамбургеров, их хватит и на любое меньшее количество. Ищем последнее подходящее значение бинарным поиском. Верхнюю границу получаем удвоением.

Для произведений используем `__int128`: промежуточная стоимость может переполнить `long long`, даже если ответ в него помещается.

Сложность: $O(|recipe|+\log answer)$ по времени и $O(1)$ дополнительной памяти.

→ Решение: [`examples/zc_hamburgers.cpp`](examples/zc_hamburgers.cpp).

## Итоги тестирования

Задачи проверяют материал занятий 5–8:

- множества и словари — задачи 1 и 5;
- стек и его применение — задачи 2 и ZA;
- линейные проходы, суффиксный минимум и скользящее окно — задачи 3, 4 и ZB;
- бинарный поиск в массиве — задача 6;
- бинарный поиск по ответу — задачи 7 и ZC.

Перед отправкой решения проверьте строгие неравенства, случай `n = 1`, включённость границ запросов, переполнение сумм и произведений, а также перевод индексов из нулевой нумерации в нумерацию условия.
