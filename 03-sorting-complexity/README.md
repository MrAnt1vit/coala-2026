## Асимптотика

Асимптотика описывает, как растут время работы и память алгоритма при росте входа. Обычно нас интересует **порядок роста**, а не точное число операций.

Например, если ограничение по времени — 1 секунда, то программа с примерно $10^8$ простых операций часто уже находится на границе допустимого. Это не точное правило: стоимость операции, язык и платформа тоже важны. Но оценка сложности позволяет отсеять заведомо неподходящие решения ещё до запуска.

> [!IMPORTANT]
> В олимпиадных задачах нужно оценивать алгоритм для **максимальных** ограничений. Решение, которое мгновенно работает на десяти числах, может не успеть на $10^5$.

### Что означает $O(...)$

Запись $O(f(n))$ показывает, как порядок работы зависит от размера входа $n$. В ней опускают константы и слагаемые, которые при больших $n$ растут медленнее:

| Выражение | Асимптотика |
| --- | --- |
| $O(2 + 8)$ | $O(1)$ |
| $O(2n)$ | $O(n)$ |
| $O(n^2 + 5n + 10)$ | $O(n^2)$ |
| $O(n \log n + n)$ | $O(n \log n)$ |

Если вход состоит из двух независимых частей размеров $n$ и $m$, не надо заменять их одной буквой без причины: проход по обоим массивам имеет сложность $O(n + m)$, а перебор всех пар — $O(nm)$.

<details>
<summary>Как оценивать блоки кода</summary>

1. Последовательные действия складываем: $O(n) + O(n) = O(n)$.
2. Вложенные циклы с $n$ итерациями каждый обычно перемножаем: $O(n^2)$.
3. Если на каждом шаге размер уменьшается вдвое, получается $O(\log n)$.
4. Условие внутри цикла само по себе не меняет число итераций, если цикл всё равно проходит весь массив.

```cpp
// O(n): один проход
for (int i = 0; i < n; i++) {
    sum += a[i];
}

// O(n * m): все пары элементов двух массивов
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        // работа с a[i] и b[j]
    }
}

// O(log n): n принимает значения n, n / 2, n / 4, ...
for (int x = n; x > 0; x /= 2) {
    // работа
}
```

→ Запускаемый набор коротких примеров: [`examples/complexity_examples.cpp`](examples/complexity_examples.cpp).

</details>

### Частые порядки роста

| Сложность | Типичный пример | Когда это реалистично |
| --- | --- | --- |
| $O(1)$ | доступ по индексу, присваивание | почти всегда |
| $O(\log n)$ | двоичный поиск | очень быстро |
| $O(\sqrt n)$ | перебор делителей до корня | обычно хорошо |
| $O(n)$ | один проход по массиву | хорошо для больших $n$ |
| $O(n \log n)$ | быстрая сортировка | хорошо для $n \approx 10^5$ и больше |
| $O(n^2)$ | два полных вложенных цикла | годится только при небольшом $n$ |

> [!TIP]
> Перед написанием решения сопоставьте ограничение с ожидаемой сложностью. При $n = 10^5$ двойной цикл почти наверняка не подходит, а `sort` обычно подходит.

## Квадратичные сортировки

Задача сортировки: переставить элементы массива так, чтобы они шли в неубывающем порядке. Три алгоритма ниже работают за $O(n^2)$ в худшем случае. На больших данных вместо них почти всегда используют `std::sort`, но эти реализации нужны, чтобы почувствовать устройство сортировок и научиться анализировать циклы.

### Пузырьковая сортировка

Идём по массиву и меняем местами соседей, если они стоят в неправильном порядке. После одного полного прохода наибольший элемент «всплывает» в конец. После следующего прохода на место встаёт следующий по величине.

| Проход | Массив после прохода |
| --- | --- |
| начало | `3 1 8 2 10` |
| 1 | `1 3 2 8 10` |
| 2 | `1 2 3 8 10` |

→ Запускаемый пример: [`examples/bubble_sort.cpp`](examples/bubble_sort.cpp).

<details>
<summary>Реализация и оценка</summary>

```cpp
for (int last = n - 1; last > 0; last--) {
    bool changed = false;
    for (int i = 0; i < last; i++) {
        if (a[i] > a[i + 1]) {
            swap(a[i], a[i + 1]);
            changed = true;
        }
    }
    if (!changed) {
        break;
    }
}
```

В худшем случае это $O(n^2)$: почти $n$ проходов по почти $n$ элементам. Флаг `changed` даёт $O(n)$ для уже отсортированного массива, но не меняет худшую оценку.

</details>

### Сортировка выбором

На шаге `last` ищем максимум среди ещё незафиксированных элементов `a[0]` … `a[last]` и ставим его на позицию `last`. Так после каждого шага правая часть массива уже отсортирована.

→ Запускаемый пример: [`examples/selection_sort.cpp`](examples/selection_sort.cpp).

<details>
<summary>Почему получается <code>O(n²)</code></summary>

На первом шаге ищем максимум среди $n$ элементов, затем среди $n - 1$, и так далее:

$$
n + (n - 1) + \dots + 1 = \frac{n(n + 1)}{2} = O(n^2).
$$

Перестановок здесь всего не более $n$, но сравнений всё равно квадратично много.

</details>

### Сортировка вставками

Поддерживаем отсортированный префикс. Берём очередной элемент и сдвигаем вправо все большие элементы префикса, пока не найдём для него место.

→ Запускаемый пример: [`examples/insertion_sort.cpp`](examples/insertion_sort.cpp).

<details>
<summary>Когда она бывает полезна</summary>

В худшем случае сложность $O(n^2)$. Зато на почти отсортированных маленьких массивах вставки могут быть очень удобны и быстры на практике. В отличие от пузырьковой сортировки, элемент сразу перемещается к своей позиции, а не «ползёт» через последовательность соседних обменов.

</details>

## Быстрые сортировки

### Сортировка подсчётом

Если элементы — целые числа из небольшого диапазона, можно не сравнивать элементы между собой. Создадим массив `count`: в `count[x]` будет число вхождений значения `x`. Затем выпишем каждое значение столько раз, сколько оно встретилось.

→ Запускаемый пример с отрицательными числами: [`examples/counting_sort.cpp`](examples/counting_sort.cpp).

<details>
<summary>Диапазон и сложность</summary>

Пусть $R = \max(a) - \min(a) + 1$ — число возможных значений. Тогда сортировка подсчётом работает за $O(n + R)$ и использует $O(R)$ дополнительной памяти.

Для отрицательных чисел удобно сдвигать индекс:

```cpp
int index = value - minimum;
count[index]++;
```

Алгоритм хорош, когда диапазон мал. Например, сортировать миллион оценок от 1 до 10 — отличная идея; создавать массив размера $10^9$ ради нескольких чисел — плохая.

</details>

### Сортировка слиянием

Разделяем массив на две части, рекурсивно сортируем каждую и сливаем два отсортированных массива двумя указателями. На каждом уровне рекурсии обрабатывается $n$ элементов, а уровней примерно $\log n$.

→ Запускаемый пример: [`examples/merge_sort.cpp`](examples/merge_sort.cpp).

<details>
<summary>Слияние двух отсортированных частей</summary>

Пока в обеих частях остались элементы, берём меньший из текущих. Когда одна часть закончилась, дописываем остаток другой.

```cpp
while (i < left.size() && j < right.size()) {
    if (left[i] <= right[j]) {
        result.push_back(left[i++]);
    } else {
        result.push_back(right[j++]);
    }
}
```

Итоговая сложность — $O(n \log n)$, дополнительная память — $O(n)$. Сортировка слиянием стабильна: равные элементы сохраняют относительный порядок.

</details>

### Быстрая сортировка

Выбираем опорный элемент `pivot`, раскладываем остальные на элементы не больше и не меньше него, а затем рекурсивно сортируем части. При удачных разбиениях ожидаемая сложность — $O(n \log n)$, в худшем случае — $O(n^2)$.

→ Запускаемый учебный пример: [`examples/quicksort.cpp`](examples/quicksort.cpp).

> [!WARNING]
> Не пишите собственную быструю сортировку в задаче без необходимости: легко ошибиться в разбиении или получить плохой случай. Для обычной сортировки в C++ почти всегда выбирайте `std::sort`.

## `std::sort` и компаратор

В C++ обычно сортируют так:

```cpp
#include <algorithm>

sort(a.begin(), a.end());
```

Для чисел это сортировка по возрастанию, для строк — лексикографически. У `std::sort` сложность $O(n \log n)$.

Если нужен свой порядок, третьим аргументом передают **компаратор**. Он отвечает `true`, если первый объект должен стоять **строго раньше** второго.

```cpp
bool by_abs(int x, int y) {
    return abs(x) < abs(y);
}

sort(a.begin(), a.end(), by_abs);
```

→ Запускаемый пример с несколькими компараторами: [`examples/sort_comparator.cpp`](examples/sort_comparator.cpp).

<details>
<summary>Правило для компаратора</summary>

Компаратор не должен возвращать `true` для равных элементов. Поэтому для сортировки по числу используем `<`, а не `<=`:

```cpp
// правильно
return x < y;

// неправильно: cmp(x, x) вернёт true
return x <= y;
```

Например, чтобы из строк получить минимальное возможное число после склейки, две строки `a` и `b` сравнивают так:

```cpp
bool before(string a, string b) {
    return a + b < b + a;
}
```

</details>

> [!TIP]
> Если элементы равны с точки зрения компаратора, `std::sort` не обязан сохранять их исходный порядок. Для этого существует `stable_sort`.

## Что потренировать

1. Для нескольких фрагментов с одним, двумя и тремя циклами определить сложность до запуска программы.
2. Реализовать пузырьковую и сортировку выбором самостоятельно, не подсматривая в пример.
3. Отсортировать числа из диапазона от `-100` до `100` подсчётом.
4. Отсортировать строки по длине, а при равной длине — лексикографически.
5. Для набора строк найти порядок, который даёт минимальную строку после конкатенации.

<details>
<summary>Короткий чек-лист перед отправкой решения</summary>

- Подходит ли сложность под максимальное ограничение?
- Не обращаюсь ли я к `a[i + 1]`, когда `i` уже последний индекс?
- Если используется подсчёт: не слишком ли велик диапазон значений?
- Если есть компаратор: возвращает ли он `false` для одинаковых элементов?

</details>
