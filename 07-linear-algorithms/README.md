В текущем контесте добавились отдельная базовая задача на запросы суммы и более широкий набор задач на префиксы, два указателя и монотонный стек.

Линейный алгоритм обрабатывает вход размера $n$ за $O(n)$. При этом в коде вполне может быть вложенный `while`: важен не внешний вид программы, а то, сколько раз суммарно выполняются операции.

На занятии разбираем четыре семейства приёмов:

- префиксные суммы и массив разностей;
- два указателя и скользящее окно;
- монотонный стек;
- монотонную очередь на `deque`.

## Как доказать линейную сложность

Один цикл до $n$ почти всегда даёт $O(n)$. Сложнее выглядят алгоритмы такого вида:

```cpp
for (int right = 0; right < n; ++right) {
    while (условие) {
        ++left;
    }
}
```

Нельзя просто перемножить размеры циклов и объявить $O(n^2)$. Если `left` никогда не движется назад, за весь алгоритм он увеличится не более $n$ раз. Указатель `right` тоже сделает $n$ шагов, поэтому суммарно получится не более $2n$ передвижений: $O(n)$.

Та же идея работает для стека и дека: каждый индекс один раз добавляется и не более одного раза удаляется. Такое доказательство называют **амортизационным**.

> [!IMPORTANT]
> Фраза «в среднем быстро» недостаточна. Найдите объект, который необратимо движется или удаляется, и посчитайте, сколько раз это может произойти за всё выполнение.

## Префиксные суммы

Для массива `a` длины $n$ заведём массив `pref` длины $n+1$:

$$
pref[0]=0,\qquad pref[i+1]=pref[i]+a[i].
$$

Тогда `pref[i]` — сумма первых $i$ элементов, а сумма на полуинтервале $[l,r)$ равна

$$
a[l]+a[l+1]+\ldots+a[r-1]=pref[r]-pref[l].
$$

Для привычного отрезка $[l,r]$ в нулевой индексации формула выглядит как `pref[r + 1] - pref[l]`.

```cpp
vector<long long> pref(n + 1, 0);
for (int i = 0; i < n; ++i) {
    pref[i + 1] = pref[i] + a[i];
}

long long sum = pref[r + 1] - pref[l];
```

Построение занимает $O(n)$, каждый запрос — $O(1)$. Поэтому $q$ запросов обрабатываются за $O(n+q)$ вместо $O(nq)$.

→ Решение [задачи 2 «Префиксные суммы»](https://codeforces.com/group/ByhdE7NWBK/contest/722121/problem/2): [`examples/prefix_range_sum.cpp`](examples/prefix_range_sum.cpp).

> [!WARNING]
> Даже если каждый `a[i]` помещается в `int`, сумма может не помещаться. Для `pref` почти всегда нужен `long long`.

### Максимальная сумма подотрезка

Сумма $[l,r)$ равна `pref[r] - pref[l]`. Для фиксированной правой границы выгодно вычесть минимальную префиксную сумму среди позиций левее. Во время прохода храним этот минимум и его индекс.

В [задаче 1 «Сумма чисел в массиве»](https://codeforces.com/group/ByhdE7NWBK/contest/722121/problem/1) есть дополнительные правила выбора ответа: сначала минимальная правая граница, затем максимальная левая. Поэтому:

- ответ обновляем только при **строгом** улучшении суммы;
- при равных минимальных префиксах запоминаем более поздний индекс.

→ Полное решение с обработкой равенств: [`examples/max_subarray_indices.cpp`](examples/max_subarray_indices.cpp).

### Префиксы не только для сумм

Пусть `good[i]` равно `1`, если на позиции $i$ выполнено нужное свойство, и `0` иначе. Тогда префиксные суммы по `good` за $O(1)$ считают число подходящих позиций на отрезке.

Так решается [A «Илья и запросы»](https://codeforces.com/group/ByhdE7NWBK/contest/722121/problem/A): отмечаем позиции, где соседние символы равны, и отвечаем разностью префиксов.

В задачах [E «Глеб и функционалы»](https://codeforces.com/group/ByhdE7NWBK/contest/722121/problem/E) и [ZA «Сон на лекции»](https://codeforces.com/group/ByhdE7NWBK/contest/722121/problem/ZA) нужна максимальная сумма окна фиксированной длины. Её можно считать либо префиксами, либо поддерживать скользящую сумму, вычитая ушедший элемент и добавляя новый.

## Массив разностей

Массив разностей кодирует изменения между соседними элементами:

$$
diff[0]=a[0],\qquad diff[i]=a[i]-a[i-1].
$$

Исходный массив восстанавливается префиксными суммами по `diff`. Это позволяет выполнить прибавление $x$ ко всему отрезку $[l,r]$ двумя изменениями:

```cpp
diff[l] += x;
if (r + 1 < n) {
    diff[r + 1] -= x;
}
```

После всех запросов один проход восстанавливает результат. Итого $O(n+q)$.

→ Запускаемый пример: [`examples/range_add_difference.cpp`](examples/range_add_difference.cpp).

Массив разностей полезен, только если не требуется печатать весь массив после каждого запроса. Мы сначала накапливаем изменения, а затем применяем их все сразу.

## Два указателя

Два указателя применимы, когда после движения одной границы понятно, в какую сторону надо двигать другую, и возвращаться назад не придётся.

### Окно в одном массиве

Для каждого `right` поддерживаем самый левый `left`, при котором окно подходит:

```cpp
for (int right = 0; right < n; ++right) {
    // добавили a[right] в состояние окна
    while (left <= right && окно_не_подходит) {
        // удалили a[left] из состояния окна
        ++left;
    }
    // [left, right] подходит
}
```

Главное — сформулировать **инвариант**: что именно верно про окно перед вычислением ответа.

В [задаче 3 «Сбалансированная команда»](https://codeforces.com/group/ByhdE7NWBK/contest/722121/problem/3) сначала сортируем навыки. После этого подходящая команда — подотрезок, где `a[right] - a[left] <= 5`.

→ Решение: [`examples/balanced_team.cpp`](examples/balanced_team.cpp).

Сортировка занимает $O(n\log n)$, сам проход — $O(n)$. Называть всё решение линейным нельзя.

В [задаче C «Книги»](https://codeforces.com/group/ByhdE7NWBK/contest/722121/problem/C) окно хранит сумму прочитанных книг. Все времена неотрицательны, поэтому при превышении лимита достаточно двигать левую границу вправо.

→ Решение: [`examples/books_window.cpp`](examples/books_window.cpp).

> [!WARNING]
> Если в задаче про сумму разрешены отрицательные элементы, обычное скользящее окно может перестать работать: после расширения сумма способна уменьшиться, а после сжатия — увеличиться. Нужна другая идея.

### Указатели навстречу

В [D «Алиса, Боб и шоколад»](https://codeforces.com/group/ByhdE7NWBK/contest/722121/problem/D) один указатель идёт слева, другой справа. Следующий кусок берёт тот, у кого накопленное время меньше. Каждый кусок обрабатывается один раз, поэтому сложность $O(n)$.

### Указатели по двум отсортированным массивам

В [ZB «Стильная одежда»](https://codeforces.com/group/ByhdE7NWBK/contest/722121/problem/ZB) сравниваем текущие цвета майки и штанов. Меньший цвет можно безопасно сдвинуть: с текущим большим элементом никакой ещё меньший цвет из того же массива не улучшит разность.

→ Полное решение: [`examples/stylish_clothes.cpp`](examples/stylish_clothes.cpp).

## Ближайший меньший и монотонный стек

Для каждого элемента хотим найти ближайший строго меньший слева или справа. Квадратичный поиск проверяет соседей по одному. Монотонный стек удаляет кандидатов, которые уже никогда не понадобятся.

Для ближайшего меньшего слева идём слева направо:

```cpp
while (!st.empty() && a[st.top()] >= a[i]) {
    st.pop();
}

answer[i] = st.empty() ? -1 : st.top();
st.push(i);
```

После удалений значения по индексам в стеке строго возрастают. Верхушка — ближайший оставшийся меньший элемент.

Для ближайшего меньшего **справа** симметрично идём справа налево. Именно это требуется в [задаче 4 «Великое Лайнландское переселение»](https://codeforces.com/group/ByhdE7NWBK/contest/722121/problem/4).

→ Решение: [`examples/nearest_smaller_right.cpp`](examples/nearest_smaller_right.cpp).

### Почему вложенный `while` не даёт квадрат

Каждый индекс:

1. ровно один раз попадает в стек;
2. не более одного раза удаляется из него.

Всего будет $n$ добавлений и не более $n$ удалений, то есть $O(n)$ операций.

### Строгий или нестрогий ответ

- для ближайшего **строго меньшего** удаляем `>= a[i]`;
- для ближайшего **меньшего или равного** удаляем только `> a[i]`.

Один знак равенства меняет смысл алгоритма, особенно на массивах с повторениями.

### Максимальный прямоугольник в гистограмме

В [ZD «Гистограмма»](https://codeforces.com/group/ByhdE7NWBK/contest/722121/problem/ZD) каждый столбец высоты $h$ может быть минимальной высотой прямоугольника. Нужно найти первую меньшую высоту слева и справа; между этими границами ширина равна `right - left - 1`.

Это можно сделать одним стеком: когда приходит меньшая высота, завершаем все более высокие прямоугольники. Нулевой столбец-сентинел в конце очищает стек.

→ Решение: [`examples/largest_histogram_rectangle.cpp`](examples/largest_histogram_rectangle.cpp).

В [ZE «Майк и футы»](https://codeforces.com/group/ByhdE7NWBK/contest/722121/problem/ZE) та же пара границ показывает максимальную длину окна, в котором элемент может быть минимумом. Затем ответы для меньших длин распространяются справа налево.

## Минимум в окне и монотонная очередь

Нужно найти минимум в каждом окне длины $k$. В деке храним **индексы** возможных минимумов так, чтобы значения по ним возрастали.

Для очередного индекса `i`:

1. удаляем с начала индексы, которые вышли из окна;
2. удаляем с конца элементы не меньше `a[i]` — новый элемент лучше и останется в окне дольше;
3. добавляем `i` в конец;
4. минимум текущего полного окна лежит по индексу `dq.front()`.

```cpp
while (!dq.empty() && dq.front() <= i - k) {
    dq.pop_front();
}
while (!dq.empty() && a[dq.back()] >= a[i]) {
    dq.pop_back();
}
dq.push_back(i);
```

→ Решение [задачи 5 «Минимум в окне»](https://codeforces.com/group/ByhdE7NWBK/contest/722121/problem/5): [`examples/sliding_window_minimum.cpp`](examples/sliding_window_minimum.cpp).

Дек хранит индексы, потому что значение не сообщает, вышел элемент из окна или нет. Каждый индекс добавляется и удаляется не более одного раза, значит вся обработка занимает $O(n)$.

## Как выбрать приём

| Что требуется | Что попробовать |
| --- | --- |
| Много запросов суммы по неизменяемому массиву | префиксные суммы |
| Много прибавлений на отрезке, ответ нужен после всех запросов | массив разностей |
| Самое длинное/короткое подходящее окно, условие меняется монотонно | два указателя |
| Ближайший меньший/больший элемент | монотонный стек |
| Минимум/максимум во всех окнах одной длины | монотонный дек |

## Чек-лист перед отправкой

- Есть ли нулевой элемент `pref[0]`, а сам `pref` имеет размер `n + 1`?
- Не перепутаны ли формулы для $[l,r)$ и $[l,r]$?
- Помещаются ли суммы и площади в `long long`?
- Сформулирован ли инвариант окна и действительно ли его можно восстановить только движением вправо?
- Учитывается ли стоимость сортировки перед линейным проходом?
- Хранятся ли в монотонном стеке/деке индексы, если нужны позиции или срок выхода из окна?
- Правильно ли выбран знак `>` или `>=` для элементов с одинаковыми значениями?
- Удалены ли из дека элементы, уже вышедшие из окна, до чтения `front()`?
- Доказано ли, что каждый указатель или индекс сдвигается/удаляется лишь $O(1)$ раз?
