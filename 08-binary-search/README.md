Бинарный поиск применим не только к отсортированному массиву. Его настоящая область применения — любой упорядоченный набор вариантов, в котором ответ на вопрос `ok(x)` меняется не более одного раза:

```text
false false false | true true true
                  ^ первая подходящая позиция
```

За одну проверку мы отбрасываем половину оставшегося диапазона. Поэтому среди $n$ вариантов достаточно $O(\log n)$ проверок: даже миллиард вариантов сжимается примерно за 30 шагов.

## Главное условие: монотонность

Пусть для каждого кандидата `x` мы умеем проверить свойство `ok(x)`. Бинарный поиск работает, если по мере роста `x` ответы имеют один из двух видов:

```text
false ... false, true ... true   // ищем первое true
true  ... true,  false ... false // ищем последнее true
```

Примеры:

- в отсортированном массиве условие `a[i] >= x` сначала ложно, затем истинно;
- квадрат со стороной `s` сначала не вмещает все дипломы, а начиная с некоторого `s` — вмещает;
- верёвку длины `len` можно нарезать в нужном количестве при малых `len`, но нельзя при слишком больших;
- если корабль может добраться за `d` дней, то может и за любое большее число дней: на следующем шаге единичный сдвиг ветра можно компенсировать своим ходом.

> [!IMPORTANT]
> Нельзя запускать бинарный поиск только потому, что «ответ — число». Сначала сформулируйте `ok(x)` и докажите, что значение предиката меняется не более одного раза.

## Инварианты и два шаблона

Удобнее хранить не «возможный отрезок», а две границы с известными свойствами. Границы могут быть фиктивными индексами вне массива — обращаться к ним как к элементам нельзя.

### Первое `true`

Поддерживаем инвариант:

- `left` заведомо не подходит;
- `right` заведомо подходит.

```cpp
long long left = -1; // ok(left) == false
long long right = n; // ok(right) == true

while (right - left > 1) {
    long long mid = left + (right - left) / 2;
    if (ok(mid)) {
        right = mid;
    } else {
        left = mid;
    }
}
// right — первое подходящее значение
```

### Последнее `true`

Теперь слева лежат подходящие значения, справа — неподходящие:

```cpp
long long left = 0;      // ok(left) == true
long long right = limit; // ok(right) == false

while (right - left > 1) {
    long long mid = left + (right - left) / 2;
    if (ok(mid)) {
        left = mid;
    } else {
        right = mid;
    }
}
// left — последнее подходящее значение
```

Обе границы проверяем **до** цикла. После каждой итерации инвариант должен сохраняться, а расстояние между границами — уменьшаться.

> [!WARNING]
> Ошибки вида `left = mid + 1`, `right = mid - 1` нельзя механически переносить между реализациями. Сначала зафиксируйте смысл границ и полуинтервала, затем пишите обновления.

## Поиск в отсортированном массиве

Для точного поиска элемента `x` достаточно найти первую позицию, на которой значение не меньше `x`:

```cpp
int left = -1; // здесь мысленно a[left] < x
int right = static_cast<int>(a.size()); // здесь мысленно a[right] >= x

while (right - left > 1) {
    int mid = left + (right - left) / 2;
    if (a[mid] >= x) {
        right = mid;
    } else {
        left = mid;
    }
}

if (right < static_cast<int>(a.size()) && a[right] == x) {
    cout << right; // индекс первого вхождения
} else {
    cout << -1;
}
```

Почему массив должен быть отсортирован? Только тогда условие `a[i] >= x` имеет вид `false ... false, true ... true`.

Для $q$ запросов после чтения уже отсортированного массива сложность равна $O(q\log n)$. Если массив сначала нужно отсортировать, добавляется $O(n\log n)$.

## `lower_bound` и `upper_bound`

Стандартная библиотека уже содержит два основных граничных поиска:

| Вызов | Первая позиция, где |
| --- | --- |
| `lower_bound(begin, end, x)` | значение `>= x` |
| `upper_bound(begin, end, x)` | значение `> x` |

```cpp
auto first = lower_bound(a.begin(), a.end(), x);
auto after = upper_bound(a.begin(), a.end(), x);
```

Из них сразу получаются:

- первое вхождение: `first`, если `first != a.end() && *first == x`;
- последнее вхождение: `after - 1`, если элемент существует;
- число вхождений: `after - first`;
- число элементов `<= x`: `upper_bound(...) - a.begin()`;
- число элементов `< x`: `lower_bound(...) - a.begin()`.

→ Все варианты в одной программе: [`examples/array_bounds.cpp`](examples/array_bounds.cpp).

Учебная программа печатает индексы с нуля. В задачах 1 и 2 контеста требуются индексы с единицы, поэтому к найденной позиции нужно прибавить `1`.

> [!CAUTION]
> Итератор `end()` указывает после массива, его нельзя разыменовывать. Вычитание `1` из `begin()` тоже недопустимо.

## Приближённый поиск

В [задаче A](https://codeforces.com/group/ByhdE7NWBK/contest/723169/problem/A) нужно найти ближайшее к запросу число, а при равенстве расстояний выбрать меньшее.

`lower_bound(x)` делит массив на две части. Ближайшим может быть только:

- первый элемент `>= x`;
- предыдущий элемент `< x`.

Сравнивать весь массив не нужно. Не забудьте отдельно обработать случаи, когда одной из двух позиций нет.

Разность лучше вычислять в `long long`: для значений около `-2e9` и `2e9` тип `int` может переполниться.

Та же идея границы решает [задачу B «Интересный напиток»](https://codeforces.com/group/ByhdE7NWBK/contest/723169/problem/B): количество цен не больше `money` равно индексу `upper_bound(money)`. → [`examples/interesting_drink.cpp`](examples/interesting_drink.cpp).

## Бинарный поиск по ответу

Когда сам ответ заранее не перечислен в массиве, перебираем его возможные значения неявно.

### 1. Сформулировать кандидата

Например, `side` — сторона квадратной доски, `len` — длина куска верёвки, `distance` — минимальное расстояние между коровами.

### 2. Написать `ok(candidate)`

Проверка должна отвечать на вопрос «можно ли получить решение не хуже кандидата?»:

- дипломы: помещается ли хотя бы `n` прямоугольников;
- верёвочки: получается ли хотя бы `k` кусков;
- коровы: удаётся ли жадно поставить хотя бы `k` коров;
- печенье: хватает ли запасов и порошка на `candidate` печений.

### 3. Доказать монотонность

Если доска со стороной `side` подходит, любая большая тоже подходит. Если куски длины `len` нарезать нельзя, ещё более длинные тоже нельзя.

### 4. Найти правильную границу

- минимум среди подходящих — первое `true`;
- максимум среди подходящих — последнее `true`.

→ Первое `true`: [задача 3 «Дипломы»](https://codeforces.com/group/ByhdE7NWBK/contest/723169/problem/3) и [`examples/diplomas.cpp`](examples/diplomas.cpp).

→ Последнее `true`: [задача 5 «Верёвочки»](https://codeforces.com/group/ByhdE7NWBK/contest/723169/problem/5) и [`examples/ropes.cpp`](examples/ropes.cpp).

→ Проверка за $O(n)$: [задача D «Коровы — в стойла»](https://codeforces.com/group/ByhdE7NWBK/contest/723169/problem/D) и [`examples/aggressive_cows.cpp`](examples/aggressive_cows.cpp).

Если одна проверка работает за $O(f(n))$, а ширина целочисленного диапазона равна $C$, общая сложность — $O(f(n)\log C)$.

> [!TIP]
> Монотонность ещё не означает, что бинарный поиск обязателен. В задаче C после добавления `x` родителей нужно `3(K + x) >= N + x`, откуда сразу получается `x >= (N - 3K) / 2` с округлением вверх и ограничением снизу нулём. Формула проще и точнее поиска.

## Границы и переполнение

### Граница должна быть доказана

Для верёвок правая неподходящая граница — `max_length + 1`: получить кусок длиннее любой исходной верёвки невозможно. Для максимальной медианы достаточно `median + k + 1`: уже один средний элемент потребовал бы больше `k` увеличений.

Если естественная верхняя граница неизвестна, можно удваивать её:

```cpp
long long right = 1;
while (!ok(right)) {
    right *= 2;
}
```

Так можно делать, только если существование ответа доказано и удвоение не переполнит тип.

### Безопасная середина

Вместо `(left + right) / 2` пишите:

```cpp
long long mid = left + (right - left) / 2;
```

Это защищает от переполнения суммы. Но выражения внутри `ok` тоже требуют внимания:

- `side / w * (side / h)` может переполнить `long long`;
- `a[i] * count` может переполниться до вычитания;
- сумма большого числа требуемых ресурсов может выйти за границы типа.

Для промежуточных вычислений удобно использовать `__int128` или прекращать подсчёт сразу после достижения нужного порога.

→ Защищённая проверка ресурсов: [задача E «Волшебный порошок — 1»](https://codeforces.com/group/ByhdE7NWBK/contest/723169/problem/E) и [`examples/magic_powder.cpp`](examples/magic_powder.cpp).

## Вещественный бинарный поиск

В [задаче 4](https://codeforces.com/group/ByhdE7NWBK/contest/723169/problem/4) функция

$$
f(x)=x^2+\sqrt{x}
$$

строго возрастает при $x\ge 0$. Поэтому можно искать границу между `f(x) < C` и `f(x) >= C`.

Для `double` надёжнее выполнить фиксированное число итераций:

```cpp
for (int iteration = 0; iteration < 100; ++iteration) {
    double mid = (left + right) / 2.0;
    if (f(mid) >= target) {
        right = mid;
    } else {
        left = mid;
    }
}
```

Сто итераций уменьшают исходный интервал примерно в $2^{100}$ раз — для `double` этого более чем достаточно.

> [!WARNING]
> Не проверяйте `f(mid) == C`: большинство вещественных значений нельзя точно представить в двоичном формате. Также не используйте только `while (right - left > eps)`, если при больших числах середина из-за округления перестала отличаться от границ.

Выводите несколько запасных знаков: `fixed << setprecision(10)`. → [`examples/real_root.cpp`](examples/real_root.cpp).

## Чек-лист перед отправкой

- Массив действительно отсортирован до поиска?
- Сформулировано ли, что означает `ok(x)`?
- Доказана ли монотонность предиката?
- Известно ли, какое значение нужно: первое `true` или последнее `true`?
- Выполняется ли инвариант на начальных границах?
- Цикл гарантированно уменьшает расстояние между границами?
- Проверены ли `begin()` и `end()` перед разыменованием соседей?
- Не переполняются ли середина, произведения и суммы внутри `ok`?
- Для `double` используется фиксированное число итераций и достаточная точность вывода?
- В итоговой сложности учтена стоимость одной проверки?
