## `set`: упорядоченное множество

`set<T>` хранит **уникальные** элементы типа `T` в отсортированном порядке. Это удобно, когда нужно быстро отвечать на вопросы «есть ли такое значение?», «какое ближайшее не меньше `x`?» или «сколько различных чисел встретилось?».

```cpp
#include <set>

set<int> s = {8, 3, 8, 1}; // внутри: 1, 3, 8
s.insert(5);               // внутри: 1, 3, 5, 8
```

→ Запускаемый пример: [`examples/set_basics.cpp`](examples/set_basics.cpp).

> [!IMPORTANT]
> Повторная вставка в `set` не создаёт второй такой же элемент. Именно этим `set` отличается от `vector` и `multiset`.

<details>
<summary>Основные методы <code>set</code></summary>

| Выражение | Что делает | Сложность |
| --- | --- | --- |
| `s.insert(x)` | добавляет `x`, если его ещё нет | $O(\log n)$ |
| `s.erase(x)` | удаляет `x`, если он есть | $O(\log n)$ |
| `s.count(x)` | возвращает `0` или `1` | $O(\log n)$ |
| `s.find(x)` | итератор на `x` или `s.end()` | $O(\log n)$ |
| `s.size()` | число различных элементов | $O(1)$ |
| `s.empty()` | проверка пустоты | $O(1)$ |
| `s.clear()` | удаляет все элементы | $O(n)$ |

В C++20 есть сокращение `s.contains(x)`. В материалах этого курса используется C++17, поэтому проверяем наличие так:

```cpp
if (s.find(x) != s.end()) {
    // x есть в set
}
```

`count(x) != 0` тоже работает, но `find` сразу даёт итератор, если элемент понадобится дальше.

</details>

### Итераторы и границы поиска

`set` поддерживает итераторы — «указатели» на элементы контейнера. `begin()` указывает на минимальный элемент, а `end()` — на позицию **после** последнего; `end()` нельзя разыменовывать.

```cpp
set<int> s = {2, 4, 7, 10};

auto it = s.lower_bound(5); // указывает на 7
auto next = s.upper_bound(7); // указывает на 10
```

→ Запускаемый пример с проверкой границ: [`examples/set_bounds.cpp`](examples/set_bounds.cpp).

<details>
<summary><code>find</code>, <code>lower_bound</code>, <code>upper_bound</code></summary>

| Выражение | Результат |
| --- | --- |
| `s.find(x)` | элемент, равный `x`, либо `end()` |
| `s.lower_bound(x)` | первый элемент, который **не меньше** `x` |
| `s.upper_bound(x)` | первый элемент, который **строго больше** `x` |

Все три операции работают за $O(\log n)$. Перед `*it` всегда проверьте `it != s.end()`:

```cpp
auto it = s.lower_bound(x);
if (it != s.end()) {
    cout << *it << '\n';
}
```

Удалить ровно тот элемент, на который указывает итератор, можно так: `s.erase(it)`.

</details>

### Задача из занятия: запросы к множеству

Пусть приходят команды:

- `ADD x` — добавить число;
- `PRESENT x` — вывести `YES` или `NO`, есть ли число;
- `COUNT` — вывести число различных сохранённых значений.

`set` напрямую соответствует такой задаче: `insert`, `find` и `size` выполняют нужные действия.

→ Полная программа: [`examples/online_set.cpp`](examples/online_set.cpp).

## `map`: словарь ключ—значение

`map<Key, Value>` хранит пары «ключ—значение». Ключи уникальны и отсортированы. По ключу можно быстро найти, например, количество появлений слова, номер ученика или список данных для конкретного города.

```cpp
#include <map>

map<string, int> score;
score["Ada"] = 100;
score["Ada"] += 5;
```

Почти все операции поиска, добавления и удаления имеют сложность $O(\log n)$, где $n$ — число ключей.

→ Пример частотного словаря: [`examples/map_frequency.cpp`](examples/map_frequency.cpp).

<details>
<summary>Доступ по ключу и важное отличие <code>[]</code> от <code>at</code></summary>

`mp[key]` возвращает значение по ключу. Если ключа ещё нет, `map` **создаст** его со значением по умолчанию: для `int` это `0`, для `string` — пустая строка.

```cpp
map<string, int> frequency;
frequency["cat"]++; // создаёт ключ "cat" со значением 0, затем делает 1
```

Это идеально для подсчёта частот, но опасно для одной лишь проверки существования: `mp["missing"]` незаметно изменит словарь. Для проверки используйте `find`:

```cpp
auto it = mp.find(key);
if (it != mp.end()) {
    cout << it->second << '\n';
}
```

`mp.at(key)` не создаёт ключ, но бросает исключение, если ключ отсутствует. В олимпиадном решении обычно удобнее явно проверить `find`.

</details>

<details>
<summary>Обход <code>map</code></summary>

Элемент `map` — это пара. У неё есть поля `first` (ключ) и `second` (значение):

```cpp
for (const auto& item : mp) {
    cout << item.first << " -> " << item.second << '\n';
}
```

В C++17 можно сразу разложить пару:

```cpp
for (const auto& [key, value] : mp) {
    cout << key << " -> " << value << '\n';
}
```

Пары идут по возрастанию ключей. → Запускаемый пример: [`examples/map_iteration.cpp`](examples/map_iteration.cpp).

</details>

### Методы `map`

| Выражение | Что делает | Сложность |
| --- | --- | --- |
| `mp[key]` | читает или создаёт значение | $O(\log n)$ |
| `mp.find(key)` | пара с ключом `key` или `end()` | $O(\log n)$ |
| `mp.erase(key)` | удаляет пару по ключу | $O(\log n)$ |
| `mp.lower_bound(key)` | первая пара с ключом не меньше `key` | $O(\log n)$ |
| `mp.upper_bound(key)` | первая пара с ключом больше `key` | $O(\log n)$ |
| `mp.size()` / `mp.empty()` | размер / проверка пустоты | $O(1)$ |

Для итератора `it` ключ — `it->first`, значение — `it->second`.

## `unordered_set` и `unordered_map`

`unordered_set` и `unordered_map` тоже хранят уникальные ключи, но не поддерживают порядок: элементы размещаются по хешу. В среднем поиск, вставка и удаление занимают $O(1)$; в худшем случае — $O(n)$.

```cpp
#include <unordered_set>

unordered_set<int> used;
used.insert(42);
if (used.find(42) != used.end()) {
    cout << "found\n";
}
```

→ Пример различий с упорядоченным `set`: [`examples/unordered_containers.cpp`](examples/unordered_containers.cpp).

> [!WARNING]
> У `unordered_set` и `unordered_map` нет отсортированного порядка, поэтому нельзя использовать `lower_bound` и `upper_bound` для поиска соседей. Порядок обхода также не определён.

| Нужен порядок ключей? | Контейнер |
| --- | --- |
| Да: минимальный элемент, сосед, диапазон | `set` / `map` |
| Нет: только наличие или значение по ключу | `unordered_set` / `unordered_map` |

## `multiset` и `multimap`

`multiset` хранит элементы с повторениями, а `multimap` — несколько пар с одинаковым ключом. Оба контейнера упорядочены, поэтому основные операции имеют сложность $O(\log n)$.

```cpp
multiset<int> bag = {1, 1, 3};
cout << bag.count(1); // 2
```

→ Запускаемый пример: [`examples/multiset.cpp`](examples/multiset.cpp).

<details>
<summary>Нюансы удаления и <code>multimap</code></summary>

У `multiset` вызов `s.erase(value)` удаляет **все** вхождения `value`. Чтобы удалить только одно, сначала найдите итератор:

```cpp
auto it = s.find(value);
if (it != s.end()) {
    s.erase(it);
}
```

У `multimap` нет `operator[]` и `at`, потому что по одному ключу может быть несколько значений. Добавлять пары нужно через `insert` или `emplace`:

```cpp
multimap<string, int> results;
results.emplace("Ada", 100);
results.emplace("Ada", 95);
```

Чтобы перебрать все пары с ключом `key`, используйте диапазон `[lower_bound(key), upper_bound(key))`.

</details>

## Как выбрать контейнер

| Нужно хранить | Нужен порядок? | Контейнер |
| --- | --- | --- |
| уникальные значения | да | `set` |
| уникальные значения | нет | `unordered_set` |
| одно значение для каждого ключа | да | `map` |
| одно значение для каждого ключа | нет | `unordered_map` |
| значения с повторениями | да | `multiset` |
| несколько значений для одного ключа | да | `multimap` |

<details>
<summary>Чек-лист перед отправкой решения</summary>

- Нужны ли повторения? Если нет — `set` или `map`.
- Нужен ли отсортированный порядок, сосед или поиск по диапазону? Если да — не `unordered_...`.
- Не создаёт ли `mp[key]` новый ключ там, где требуется только проверка?
- Проверен ли итератор на `end()` перед разыменованием?
- В `multiset` удаляется одно вхождение или все? Для одного нужен `erase(iterator)`.

</details>
