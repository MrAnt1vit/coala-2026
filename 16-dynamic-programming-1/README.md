## Как придумать динамику

В задаче на ДП сначала выбирают, **что означает одна ячейка** массива `dp`. Например, `dp[i]` может быть количеством способов попасть в точку `i`, наибольшим выигрышем при завершении в `i` или минимальным числом операций для получения `i`. Из одного номера `i` смысл `dp[i]` не следует: его нужно сформулировать словами.

Затем ответьте на пять вопросов:

1. **Состояние:** какую подзадачу решает `dp[i]`?
2. **База:** какие первые ответы известны без вычисления?
3. **Переход:** из каких уже решённых подзадач получается `dp[i]` и почему перечислены все варианты?
4. **Порядок:** посчитаны ли нужные значения к моменту вычисления `dp[i]`?
5. **Ответ:** в какой ячейке он лежит и требуется ли восстановить сами действия?

На занятии эту схему сравнили с математической индукцией: известна база, а верный переход позволяет двигаться к следующим состояниям. Чтобы переход действительно доказывал ответ, нужно проверить, что он рассматривает **все** допустимые варианты и не использует ещё не вычисленные значения.

Для подсчёта способов **складывают** количества из непересекающихся вариантов. Для лучшего результата берут **максимум** или **минимум** по вариантам. Нельзя складывать максимум двух путей и нельзя брать максимум от количества способов: сначала определите смысл состояния.

У чисел Фибоначчи $f_0=0$, $f_1=1$ и $f_i=f_{i-1}+f_{i-2}$. Прямая рекурсия без запоминания многократно считает одни и те же числа. Если заполнить массив слева направо, каждое $f_i$ вычисляется один раз: время $O(n)$, память $O(n)$. В дальнейшем будем так же записывать результат каждой подзадачи, прежде чем он понадобится следующей.

## 1. Кузнечик: подсчёт способов

Кузнечик стоит на столбике $1$. За прыжок он перемещается на один или два столбика вправо. Сколько разных последовательностей прыжков приведут на столбик $n$?

Пусть $dp[i]$ — **число способов попасть на столбик $i$**. На первом столбике кузнечик уже стоит, поэтому $dp[1]=1$: пустая последовательность прыжков тоже один способ. На второй он может попасть только с первого, значит $dp[2]=1$.

Последний прыжок на $i$ сделан либо с $i-1$, либо с $i-2$. Эти случаи покрывают все разрешённые прыжки и не пересекаются: у одного пути не может быть одновременно двух разных последних прыжков. Поэтому при $i\ge3$:

$$dp[i]=dp[i-1]+dp[i-2].$$

Для $n=5$ получаем `1, 1, 2, 3, 5`, ответ $5$. Здесь важен не сам ряд Фибоначчи, а доказательство: всякий путь учтён ровно один раз. Заполняем массив по возрастанию `i`; время $O(n)$. [Полная программа](examples/grasshopper.cpp).

Этот же приём работает с путями в ориентированном графе без циклов: если известны числа путей до всех предшественников вершины, их можно сложить. На занятии это показано на схеме графа; для наших линейных задач вершинами служат номера столбиков или ступеней.

## 2. Лестница: наибольшая сумма

Есть $n$ ступеней с числами $a_1,\ldots,a_n$. Из подножия (позиция $0$) можно шагнуть на одну или две ступени. Нужно закончить на $n$ и получить наибольшую сумму чисел на посещённых ступенях. Числа могут быть отрицательными.

Пусть $dp[i]$ — **наибольшая сумма пути, который заканчивается именно на ступени $i$**. Подножие не даёт очков: $dp[0]=0$, а $dp[1]=a_1$. На ступень $i$ можно прийти с $i-1$ или $i-2$. Оба варианта получают одинаковое добавочное число $a_i$, поэтому

$$dp[i]=a_i+\max(dp[i-1],dp[i-2])\qquad(i\ge2).$$

При $i=2$ второй предшественник — подножие, так что можно сразу шагнуть на вторую ступень. Например, для $a_1=-10$, $a_2=2$ правильный ответ равен $2$, а не $-8$. Не заменяйте отрицательные промежуточные суммы нулём: путь обязан закончиться на конкретной ступени. Для `n=1` ответ $a_1$; в общем случае он лежит в $dp[n]$. Время $O(n)$, память $O(n)$; если нужен только итог, достаточно двух предыдущих значений. [Полная программа](examples/staircase.cpp).

Сравните с «Кузнечиком»: геометрия прыжков та же, но смысл состояния другой. Там мы складывали **числа способов**, здесь выбираем **лучший из двух путей**.

## 3. Зайчик: недоступные состояния

Зайчик начинает в клетке $1$ и должен попасть в клетку $n$. За прыжок он перемещается на $1$, $3$ или $5$ клеток. Часть клеток — болото (`w`), а на клетке с символом `"` растёт трава. Требуется собрать как можно больше травы; если до последней клетки добраться нельзя, ответ `-1`.

Заведём $dp[i]$ для клетки с индексом `i` от нуля: это **максимум травы на пути, закончившемся в этой клетке**. Для недостижимой клетки используем специальное значение $-\infty$ (в коде — достаточно маленькое число). Начальная клетка имеет $dp[0]=0$. Болото остаётся недостижимым. Для остальных клеток рассматриваем только существующих предшественников:

$$dp[i]=\max_{d\in\{1,3,5\},\ i-d\ge0}dp[i-d]+g_i,$$

где $g_i=1$, если в клетке трава, и $g_i=0$ иначе. **Прибавлять её можно только к достижимому предшественнику.** Иначе недоступный путь может внезапно превратиться в допустимый. Ответ — $dp[n-1]$, если значение достижимо, иначе `-1`. Поскольку на клетку проверяются лишь три прыжка, время $O(n)$. [Полная программа](examples/rabbit.cpp).

## 4. Калькулятор: минимум операций и восстановление пути

Из числа $1$ нужно получить $n$ за наименьшее число операций. Разрешено прибавить $1$, умножить на $2$ или умножить на $3$. Требуется вывести и минимум операций, и одну подходящую последовательность чисел.

Пусть $dp[i]$ — **минимум операций для получения $i$ из $1$**. База: $dp[1]=0$. Перед последним действием число было равно $i-1$; если $i$ чётно, возможно также $i/2$; если делится на $3$, возможно $i/3$. Поэтому начинаем с $dp[i-1]+1$ и улучшаем ответ доступными вариантами:

```cpp
dp[i] = dp[i - 1] + 1;
pred[i] = i - 1;
if (i % 2 == 0 && dp[i / 2] + 1 < dp[i]) {
    dp[i] = dp[i / 2] + 1;
    pred[i] = i / 2;
}
if (i % 3 == 0 && dp[i / 3] + 1 < dp[i]) {
    dp[i] = dp[i / 3] + 1;
    pred[i] = i / 3;
}
```

В `pred[i]` запоминаем число перед последней операцией. После заполнения идём от `n` по `pred` к `1`, затем разворачиваем полученный список. Для $n=10$ один оптимальный путь — $1\to3\to9\to10$ (три операции). Другой путь той же длины тоже допустим. При равенстве кандидатов код сохраняет ранее выбранный вариант. Время и память — $O(n)$. [Полная программа](examples/calculator.cpp).

В Notion описаны два способа восстановления: сохранять предшественника сразу или находить его позже сравнением с уже готовыми `dp`. Первый способ проще для проверки; именно его мы использовали. На занятии показан и второй способ.

## 5. Взрывоопасные контейнеры: узнаём знакомую задачу

Строим башню из $n$ контейнеров двух видов: с тротилом и без него. Два контейнера с тротилом не должны стоять рядом. Сколько возможных башен? Если обозначить тротил через `1`, а безопасный контейнер через `0`, задача превращается в подсчёт двоичных строк длины $n$ без соседних единиц.

Пусть $dp[i]$ — число допустимых строк длины $i$. Есть одна пустая строка: $dp[0]=1$. Для длины $1$ варианты `0` и `1`, поэтому $dp[1]=2$.

Разделим строки длины $i$ по концу. Если последний символ `0`, его можно дописать к любой допустимой строке длины $i-1$: $dp[i-1]$ вариантов. Если последний символ `1`, перед ним обязательно стоит `0`, то есть к допустимой строке длины $i-2$ дописывается `01`: $dp[i-2]$ вариантов. Оба случая допустимы, не пересекаются и охватывают все строки. Для $i\ge2$ получаем

$$dp[i]=dp[i-1]+dp[i-2].$$

Например, для $n=2$ допустимы `00`, `01`, `10`, ответ $3$. Для $n=3$ ответ $5$. Формула совпала с «Кузнечиком», но **база другая**, потому что здесь считаются строки, а там пути от первого столбика. При ограничении $n\le45$ ответ помещается в `long long`. [Полная программа](examples/containers.cpp).

## Главное к запоминанию

- Сначала сформулируйте смысл `dp[i]` словами. От него зависят база, действие в переходе и место ответа.
- Доказывая переход, перечислите все варианты последнего шага и проверьте, что они не пересекаются.
- Для количества способов используйте сумму; для наилучшей стоимости — максимум или минимум.
- Недостижимые состояния нужно обрабатывать явно. Переход из них не создаёт допустимого пути.
- Если требуется сама последовательность действий, сохраняйте предшественника и идите от ответа к базе.

## Самопроверка

1. В «Кузнечике» чему равны $dp[1]$, $dp[2]$, $dp[3]$ и почему нельзя взять $dp[1]=0$?

   <details><summary>Ответ</summary>

   $dp[1]=1$: уже находиться на первом столбике — один способ. $dp[2]=1$, поскольку есть один прыжок с первого. $dp[3]=dp[2]+dp[1]=2$: `1→2→3` и `1→3`. Если положить $dp[1]=0$, прямой прыжок `1→3` не будет посчитан.

   </details>

2. На лестнице с числами $-5, 2, -1$ чему равен максимум для третьей ступени?

   <details><summary>Ответ</summary>

   $dp[0]=0$, $dp[1]=-5$, $dp[2]=2+\max(-5,0)=2$, $dp[3]=-1+\max(2,-5)=1$. Лучший путь: с подножия сразу на вторую, затем на третью ступень.

   </details>

3. Почему в «Калькуляторе» при подсчёте $dp[i]$ значения $dp[i/2]$ и $dp[i/3]$ уже известны?

   <details><summary>Ответ</summary>

   Мы заполняем массив от $1$ к $n$. Для $i\ge2$ числа $i-1$, $i/2$ и $i/3$ (когда деление разрешено) строго меньше $i$, поэтому соответствующие состояния уже вычислены.

   </details>
